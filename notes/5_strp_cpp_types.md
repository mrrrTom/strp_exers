    Изначальная разработка языка была под названием "C с классами", и одним из принципов разработки языка стала поддержка ООП, которая невозможна без понятия "класс". 
    Б. Страуструп пишет [1]: "Класс это тип, определяемый пользователем для отражения в коде программы некоторой концепции". Чтобы определить тип, нам нужно зафиксировать: множество значений, машинное представление и набор операций над этими значениями [2]. 
    Так как пользовательские классы мы собираем из встроенных типов, то все условия из определения типа, приведённого выше, соблюдены. Что касается концепции, то её может и не быть, и это само по себе тоже будет концепцией - пока нас интересует скорее языковое средство в техническом смысле.
    И тут C++ даёт нам следующие возможности по созданию классов: конкретные классы, абстрактные классы,  иерархии классов.
* Конкретные классы
   Это такой класс, который в определении содержит представление этого класса. Например, класс вектор сразу в определении говорит, что там есть указатель на коллекцию объектов, что есть метод, выдающий размер этой коллекции и так далее. И раз это представление, которое содержится в определении, то такое представление присутствует в каждом объекте этого класса. То есть мы зафиксировали конкретные поля с конкретными типами данных для них и конкретными операциями над классом.
   Такие классы, например, помогают решать задачи, в которых нужно работать с одним типом объектов с одинаковым поведением, в которых нужны алгоритмы, определённые только для идентичных объектов.

* Абстрактные классы
    Это такие классы, которые изолируют пользователя от представления (реализации). Мы выделяем интерфейс, с которым дальше и работаем в задаче.
    Нам это необходимо, например, когда алгоритм должен уметь работать с разными объектами, над которыми можно выполнять определённый набор операций. Например, мы можем напечатать любой объект, который удовлетворяет следующему интерфейсу:
    class Printable {
    public:
        virtual void print() = 0; // нуль в данном случае означает, что реализация этого интерфейса обязана реализовать эту функцию
    }

* Иерархии классов
    Это такие классы, которые мы связали между собой наследованием. Огромное количество концепций содержит в себе наследственные связи, это позволяет классифицировать понятия и управлять соответствующими классами понятий.
    Например, мы строим онтологию садового хозяйства для поставок на кухню ресторана. Получаем такую иерархию для яблока.

    яблоко -> фрукт -> еда

    Такая иерархия позволяет нам один раз описать действие "есть", один раз описать свойства фрукта. А когда нам понадобится что-то изменить, то эти методы и свойства изменятся для всех конкретных классов, находящихся ниже по иерархии.
    class Food {
    public:
        virtual void Eat() = 0;
        virtual int GetAmount() = 0;
    };

    class Fruit : public Food {
    public:
        virtual bool IsSweet() = 0;
    };

    class Apple : public Fruit {
    public:
        Apple(int count) : _count{count} {}

        void Eat() {
            _count--;
        }

        int GetAmount() {
            return _count;
        }

        bool IsSweet() {
            return true;
        }

    private:
        int _count;
};
