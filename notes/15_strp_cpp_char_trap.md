    В C++ есть несколько символьных типов. Символьные типы относятся к
    интегральным типам - это связано с тем, что они хранятся точно
    так же, как и int.
    Как и у других интегральных типов, у символьных есть знаковые и
    беззнаковые. Вот, что Б. Страуструп пишет [1]:
    
    ```
    Запись int{c} дает целочисленное значение для символа c
    (конструируем int из символа c). Возможность конвертирования
    char в целое порождает вопрос: тип char знаковый или беззнаковый?
    256 значений в 8-битовом представлении могут интерпретироваться как
    величины от 0 до 255, или же как величины от -127 до 127. Именно так,
    а не как величины от -128 до 127, как можно было бы ожидать: стандарт
    C++ оставляет лазейку для аппаратуры с дополнение до единицы, что и
    удаляет одно значение; отсюда использование значения -128 становится
    неперносимым.
    ```

    Дело в том, что на машинном уровне знаковые типы могут представлены
    разными способами, например, дополнение до 2 - этот способ чаще всего
    и используется, а есть, например, представление со знаком, где один
    бит выделяется для обозначения знака, а в остальных располагается
    само число. Чтобы поддержать различные реализации, например, в
    стандарте С++ 11 написано:
    
    ```
    The representations of integral types shall define values by use of
    a pure binary numeration system. [Example: this International Standard
    permits 2`s complement, 1`s complement and signed magnitude representations
    for integral types. -end example]
    ```
   
    Однако с 20 версии стандарта ситуация поменялась - теперь явно прописано:
   
    ```
    The range of representable values for a signed integer type is -2^(N-1) to
    2^(N-1)-1 (inclusive), where N is called the width of the type.
    ```
    
    Таким образом, начиная с 20 стандарта непереносимость "-128" для signed
    char исправлена.
    
    Интересно, что на сайте cppreference.com написано следующее:
    
    ```
    8-bit ones` complement and sign-and-magnitude representations for char have
    been disallowed since C++11 (via the resolution of CWG issue 1759), ...
    ```
    
    Если перейти по ссылке, то описана проблема перевода литерала UTF8 0x80 в
    символьный тип. В качестве решения предложено два варианта: либо
    использовать для этого литерала unsigned char, либо для signed char
    поддержать значение 0x80. По результату был добавлен следующий параграф:
    
    ```
    For a UTF-8 string literal, each successive element of the object
    representation has the value of the corresponding code unit of the
    UTF-8 encoding of the string.
    ```
    
    Вышедобавленный параграф не похож на запрет представления символьных
    типов в со знаком.
