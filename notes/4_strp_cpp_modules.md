    C++ поддерживает раздельную компиляцию, это даёт возможность создавать полунезависимые модули.
    1. Строгое разделение логически отделяемых частей программы
    2. Минимизация времени компиляции
    
    Реализуем полиморфизм сундуков с сокровищами на уровне файлов. (ООП нам за такое по рукам бы надавал - мы должны были бы создать соответствующие классы, но не хочется перегружать пример).
    - требуемый интерфейс выделим в отдельный файл, например, для этого создадим файл treasure_chest.hpp, в котором опишем единственную функцию открытия сундука.
    #include <iostream>

    void open();

    - напишем две реализации сундука с сокровищами, для этого создадим два файла:
    treasure_chest.cpp
    #include "treasure_chest.hpp"

    void open()
    {
        std::cout << "You`ve got the treasure!";
    }

    mimic.cpp
    #include "treasure_chest.hpp"

    void open()
    {
        std::cout << "You`ve been eaten to death!";
    }

    - напишем программу, открывающую сундук.
    Этой программе ничего не известно про реализацию, она видит только заголовочный файл, в котором описана единственная функция открытия сундука
    main.cpp
    #include "treasure_chest.hpp"

    int main()
    {
        open();
        std::cout << std::endl;
        return 0;
    }

    Теперь чтобы увидить полиморфизм на уровне сборки исполняемого файла, нам нужно использовать две различные команды, которые приведут к разным ответам при вызовы исполняемого файла.
    1. g++ main.cpp treasure_chest.hpp treasure_chest.cpp
    1.1. ./a.out
    2. g++ main.cpp treasure_chest.hpp mimic.cpp
    2.1. ./a.out
