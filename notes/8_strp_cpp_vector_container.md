    В стандартной библиотеке C++ важной частью являются контейнеры и среди них наиболее используемый, наверное, vector. 
    Этот контейнер используется для хранения последовательности элементов заданного типа. 
    Контейнер содержит список элементов, к которым можно обратиться по индексу. Для примера создадим следующий пример вектора:
    
```cpp
#include <vector>

int main()
{
	std::vector<int> testVector(100);
	for (int i = 0; i < 100; i++) {
		testVector[i] = i;
	}

	return 0;
}
```

При создании объекта vector задаётся начальный размер. (Если мы явно не задали размер, то он равен нулю).
В классе vector элементы предсказуемо хранятся последовательно. (По умолчанию они хранятся в куче(heap), если не передан другой аллокатор, отличный от дефолтного).
Чтобы убедиться в расположении элементов, я использовал gdb.
1. Приведённую выше программу скомпилируем `g++ main.cpp -g` (gcc version 14.2.1)
2. Запустим отладчик `gdb ./a.out`, поставим точку остановки `b main`, начнём отладку `run`
3. С помощью команды `n` дойдём до строчки с началом цикла `for`
4. Выведем адрес объекта вектора с помощью команды `p &testVector`, получим значение 0x7fffffffddc0, с помощью команды `i r rsp` мы можем узнать, что полученный адрес находится в стеке, что соответсвует нашим ожиданием, так как мы переменную `testVector` инициализировали без использования `new()`
5. Если мы попробуем заглянуть на значение по найденному адресу с помощью команды `p *0x7fffffffddc0`, то найдём следующее значение `0x4172b0`, `p *0x4172b0` - по этому адресу мы найдём значение `0x0`. Похоже, что мы нашли дефолтные значения в инициализированном векторе
6. С помощью команд `b 10`(тут номер строчки, на которой находится команда возврата из функции) и `c` дойдём до завершения заполнения вектора в цикле
7. Чтобы убедиться, что элементы хранятся в куче последовательно, посчитаем адрес элемента 87. Каждое число `int` на моей системе занимает 4 байта, тогда отступ должен быть 4*87=348, прибавим его к началу `0x4172b0`, тогда получаем `41740C`, проверим значение по этому адресу с помощью команды `p *0x41740C`, получаем `0x57`, что является шестнадцатиричным представлением числа 87

    Недостаток этого класса в том, что сам по себе vector не содержит проверку на выход за границу диапазона, это значит, что в подобной ситуации, мы получим неопределённое поведение:
    
```cpp
    #include <vector>
    #include <iostream>

    int main()
    {
	    std::vector<int> testVector(100, 1);
	    int value = testVector[103];
	    std::cout << value;
	    return 0;
    }
```

    Однако стандартный класс вектора можно расширить, добавив проверку диапазона, которую нам предлагает Б. Страуструп[1]:

```cpp
    template<typename T>
    class Vec:public std::vector<T> {
    public:
        using vector<T>::vector;

        T& operator[](int i)
            {return vector<T>::at(i);}

        const T& operator[](int i) const
            {return vector<T>::at(i);}
    };
```

    Используемая тут операция at() при выходе за границы массива будет выбрасывать исключение типа out_of_range.
