     В языках высокого уровняя, а особенно в тех среди них, в которых не нужно заботиться о выделении и освобождении памяти, мы считаем само собой разумеющимся, что объекты можно копировать.
     Однако это не так, и реализовано такое поведение с помощью двух функций - копирующего конструктора и копирующего присваивания. 
void test(container c_1)
{
    container c_2 { c_1 }; // инициализация копированием
    container c_3;
    c_3 = c_2; // копирующее присваивание
    ...
}

    По умолчанию обе эти операции реализованы с помощью почленного копирования. И в случаях, когда у нас, например, модель только с числовыми полями, то такая реализация нас устраивает.
    Однако, когда мы говорим, например, про контейнеры, то такая реализация несёт за собой неправильное поведение.
    Например, мы копируем контейнер, но при почленном копировании мы сохраним в новый контейнер ссылки на старые ресурсы, что нарушает инвариант ресурсного дескриптора.
    C++ даёт возможность переопределить эти операции:
    
class container 
{
	private:
		int* elements;
		int size;
	public:
		int& operator[](int i)
		{
			return elements[i];
		}
		
		container(int elements_size, int val)
		{
			elements = new int[elements_size];
			for (int i = 0; i != elements_size; i++)
			{
				elements[i] = val;
			}

			size = elements_size;
		}

		container(const container& c) : elements{ new int[c.size]}, size{ c.size }
		{
			for (int i = 0; i != size; i++)
			{
				elements[i] = c.elements[i];
			}
		}

		container& operator=(const container& c)
		{
			int* e = new int[c.size];
			for (int i = 0; i != c.size; i++)
			{
				e[i] = c.elements[i];
			}

			delete[] elements;
			elements = e;
			size = c.size;
			return *this;
		}
};

int main()
{
	container c_1(3, 5);
	container c_2{c_1};
	container c_3(4, 4);
	c_3 = c_2;
	return 0;
}

    Однако возможные проблемы на этом не заканчиваются - копирование может оказаться слишком дорогостоящей операцией, например, для контейнеров с большим объёмом данных.
    В таком случае C++ нам предлагает семантику перемещения, мы определим аналогичные операции, но вместо ссылки на копируемый объект будем работать со ссылкой на rvalue. То есть с чем-то, что можно присвоить, но чему нельзя ничего присвоить, например, возвращаемый из метода результат. Такой подход позволяет нам захватить ресурсы умирающего объекта, не копируя данные, а перемещая владение ими.
    class container
    {
        ...
        container(container&& c);
        container& operator=(container&& c);
    };
