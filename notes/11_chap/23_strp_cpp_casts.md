    Естественно, раз C++ язык строгой типизации, то нам необходим вагон
    различных преобразований типов. Часть из них происходит неявно, о чем не
    всегда задумываются, а Б. Страуструп пишет [1] что таких преобразований даже
    черезчур много. Например, преобразования целого в вещественное и обратно.
    Автор приводит список возможных преобразований по возрастанию нехорошести
    этих вариантов:
    1. Конструирование с использованием {}
    2. Непривлекательные именованные преобразования:
    2.1. const_cast
    2.2. static_cast
    2.3. reinterpret_cast
    2.4. dynamic_cast
    3. C-стиль приведений
    4. Функциональный стиль

    Преобразования отсортированы по уменьшению предсказуемости получаемого
    результата, следовательно, по уменьшению надёжности и программы, написанной
    с их использованием.

    1. Конструирование с {}
    ```cpp
    auto d = double{2};
    ```
    Высокая предсказуемость обусловлена тем, что в данном случае совершаются
    только хорошо специфицированные преобразования.
    ```cpp
    int i = 2;
    auto d = double{i};
    ```
    Этот пример приведёт к ошибке... Вернее gcc выдаст предупреждение 
    
    ```
    warning: narrowing conversion of ‘i’ from ‘int’ to ‘double’ [-Wnarrowing]
    ```
    
    a clang сообщит уже об ошибке:
    ```
    error: non-constant-expression cannot be narrowed from type 'int' to
    'double' in initializer list [-Wc++11-narrowing]
    ```

    Казалось бы, при чём тут сужение - диапазон чисел у double не меньше, чем
    у int. Однако сужение может быть обусловлено не только выходом за диапазон,
    но и в буквальном смысле сужением отображением из одного множества в другое:
    могут быть такие значения int, которых нет в double[2].

    2. Непривлекательные именованные преобразования.
    Длинными и непривлекательными они сделаны специально, чтобы программист
    чаще задумывался, что он делает и зачем ему в этом деле преобразования
    типов.
    2.1. static_cast конвертирует связанные типы: в рамках одной иерархии
    классов, от интегрального к перчислению, от float к интегральному типу,
    преобразования, определённые конструкторами и операциями преобразования.
    2.2. reinterpret_cast конвертирует несвязанные типы, например от целого к
    типу указателя.
    2.3. const_cast ковертирует типы, отличающиеся друг от друга квалификаторами
    const или volatile.
    2.4. dynamic_cast динамически контролируемое преобразование в рамках
    классовой иерархии
    
    3. Преобразования в C-стиле
    ```cpp
    int i = 2;
    auto d = (double)i;
    ```

    Тут уже всё грустно - тут могут случится какие-то из преобразований:
    static_cast, reinterpret_cast, const_cast + преобразования от типа
    указателя на класс к типу указателя на его закрытый базовый класс (наследие
    C). Из-за неопределённости лучше избегать совсем таких преобразований.

    4. Функциональный стиль
    ```cpp
    int i = 2;
    auto d = double(i);
    ```
    Для встроенных типов такие преобразования эквивалентны преобразованиям
    в C-стиле, таким образом растёт неопределённость. А некоторый код вообще
    окажется непереносимым, например, на одной платформе указатель в int 
    помещается, а на другой нет - приплыли.
