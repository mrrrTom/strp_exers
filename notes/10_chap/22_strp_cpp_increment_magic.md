$cat increment_magic
    Операция увеличения на 1 или как у нас в деревне её называют - инкремент, по
    своей сути предполагается быть достаточно простой, однако сложности
    начинаются сразу.
    Какую использовать - префиксную или постфиксную?
    Разница в том, какое значение возвращается оператором - либо до изменения на
    единицу, либо после. Реализовано это может быть, например, следующим
    образом:
    ```cpp
    //префикс
    T& T::operator++() {
        // some code
        return *this;
    }

    //постфикс
    T& T::operator++(int) {
        T copy(*this);
        //some code;
        return copy;
    }

    ```

    А дальше возникает вот какое следствие [1]:
    ```cpp
        int* p = &++x; // p указывает на x
        int* q = &(x++); // ошибка: x++ не lvalue (не значение в x)
    ```

    Так происходит потому что, как мы видим из реализации, префиксный
    инкремент возвращает сам объект, сооответственно, мы можем у него спокойно
    узнать его адрес и сохранить его в переменной с типом указателя. А вот в
    случае с постфиксным инкрементом, там возвращается копия объекта, а именно
    некий временный объект, которые не является lvalue, а значит и адрес узнать
    у него нельзя.

    А может быть и плавающая ошибка с более непредсказуемым результатом.
    Например, мы хотим что-то достать из массива в теле цикла while, но при этом
    писать строчку с увеличением счётчика нам лениво и мы делаем что-то такое.
    ```cpp
    v[i] = i++;
    ```
    Что мы ожидали?
    - Что в итерации цикла для i элемента массива выставится такое же значение,
    а после этого счётчик увеличится на единицу.
    Что мы получили?
    При выполнении следующего кода (я опустил цикл и прочее для простоты)
    ```cpp
    #include <iostream>
    using namespace std;

    int main() {
    	int temp[2] = { 3, 3 };
    	int i = 0;
    	temp[i] = i++;
    	cout << temp[0] << ' ' << temp [1] << ' ' << i << endl;
    	return 0;
    }
    ```
    Я получил вывод: ```3 0 1```
    То есть сначала выполнилось правое выражение, вернувшее значение 0 и
    увеличившее i, а затем для индекса i установилось значение 0. Это получилось
    потому что мой компилятор сделал следующее (``` g++ main -S -masm=intel```):

    ```s
    // три значения отложили на стеке
	mov	DWORD PTR [rbp-12], 3
	mov	DWORD PTR [rbp-8], 3
	mov	DWORD PTR [rbp-4], 0 // наш счётчик

	mov	eax, DWORD PTR [rbp-4] // положили 0 в eax
	lea	edx, [rax+1] // с помощью магии адрессной арифметики положили в edx i+1
	mov	DWORD PTR [rbp-4], edx // теперь в переменную i положили i+1
	mov	edx, DWORD PTR [rbp-4] // в edx положили i+1
	movsx	rdx, edx // в rdx положили i+1
	mov	DWORD PTR [rbp-12+rdx*4], eax
    // а тут по адресу начала массива + (i+1)*4 положили
    // eax, где лежит начальное значение i == 0
    ```
    И это всё полностью соответствует стандарту! Ведь порядок вычисления
    выражений неопределён. Вот префиксный инкремент гарантирует, что
    увеличение i произойдёт до возврата результата выполнения операции.
